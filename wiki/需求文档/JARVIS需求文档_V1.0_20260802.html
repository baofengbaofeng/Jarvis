§2 · project-background

2. 项目背景与定位

2.1 问题陈述

当前市面 AI 工具各自为政：豆包桌面端擅长办公但缺乏编程 Agent 能力；Cursor/Codex 专注编程但办公场景覆盖不足；Multica 提供 Agent 团队管理但需要独立 Runtime。用户希望拥有一款统一的本地桌面 AI 平台，既能处理日常办公，又能执行编程任务，并支持自定义多 Agent 协作，同时兼容 Multica 远端调度协议。

2.2 产品定位

一句话定位：JARVIS 是面向个人办公的跨平台本地 AI Agent 平台——豆包式交互体验 + Cursor 级编程能力 + Multica 兼容的多 Agent 协作基础设施。

2.3 参考产品能力矩阵

参考产品借鉴能力JARVIS 关系
豆包桌面端主界面交互、划词、写作、PDF 伴读、联网搜索UI/UX 主要参考
Cursor代码编辑、Agent 模式、MCP、@引用、Diff 预览编程 Agent 能力参考
Codex (OpenAI)沙箱执行、并行 Task、Git/PR、Plan 模式Task 执行模型参考
OpenCode开源 Agent、多 Provider、LSP、Plugin 扩展Provider 抽象参考
OpenClaw持久记忆、工具策略、多渠道（V1 不做 IM）Agent 工具策略参考
MulticaAgent 配置、Skills、Squad、Daemon/Runtime 协议代码实现优先参考

本地模式（默认） Agent 在本机队列中直接执行任务；配置存 SQLite（本地优先，无需联网即可启动 App，模型调用需 Provider 在线） 无外部服务 纳入

6.5 模型策略（Q4 已确认）

原则说明
无预设模型应用内不内置任何 model id 列表；所有模型由用户在 Provider 配置中自行定义添加
Provider 类型至少支持两类接口规范：OpenAI API（/v1/chat/completions 等）、Anthropic API（/v1/messages 等）
自定义 Base URL通过 B2 配置；兼容 OpenAI 格式的第三方服务（含 Ollama、国内中转）均作为自定义 Provider 接入
Model 字段Agent 绑定时从用户已注册的自定义模型中选择，不支持应用级硬编码默认模型
参数映射temperature、max_tokens、reasoning 等参数按 Provider 类型映射到对应 API 字段

6.4 多语言（i18n）要求

项要求
必须语言简体中文（zh-CN）、英文（en）
覆盖范围全部 UI 文案、系统消息、设置项、错误提示、托盘菜单、通知内容
不覆盖用户/Agent 对话内容、Agent 自定义指令、Skills 正文（保持用户原始语言）
语言切换设置页可切换；跟随系统语言为可选项
资源组织packages/i18n/locales/{zh-CN,en}/*.json
开发约束禁止硬编码 UI 字符串；新增界面必须同时提供 zh-CN / en 翻译

§11 · confirmed-decisions

11. 已确认决策（2026-08-02）

#问题决策影响范围
Q1 多 Agent 协作是否完全对齐 Multica Squad？ A — 完全对齐 F8/F9 按 Multica Squad 协议实现；Leader + @成员分派；遵循 Squad Operating Protocol
Q2 Multica 服务端使用方式？ A — Multica Client（客户端协议全量） H1 + H3 纳入；本机 jarvis-daemon 即 Multica Client，支持 Server↔Client 全部协议并被 Server 直接调用（决策二 A 撤销）；H2 Client 产品功能排除（不提供 App 内 Multica 登录/Issue/Autopilot）
Q3 代码编辑深度？ B — 轻量形态 聊天 + 文件树 + Diff；E5 排除；E11/K3 降级为轻量代码面板；Agent 改代码仍通过工具链
Q4 模型接入策略？ 全自定义模式 不预设任何模型；新增 B13；Provider 须兼容 OpenAI / Anthropic API；用户自行注册 model id
Q5 全局系统能力跟进时机？ B — V2.0 A3、I1–I4、I6–I7、I9–I10 维持排除至 V2.0；V1.0 保留 I5/I8 最小实现

11.1 Q1 落地要点 — Multica Squad 对齐

  • 本地 Squad 数据结构对齐 Multica：Leader Agent、成员列表、角色说明、Squad Instructions
  • Leader 首次接单时将父 Task 置为 in_progress；整体完成后置为 in_review
  • 成员分派通过 @mention；结合 L12–L15 消息总线与调用链
  • 参考 Multica 文档：server/internal/squad/、Squad Operating Protocol

11.2 Q2 落地要点 — 仅 Multica Runtime

  • 实现 jarvis-agent CLI（Go 瘦协议壳，内嵌 Node 执行 packages/core 的 REACT loop，决策一 A），作为 Multica Client 被 Server 直接调用
  • jarvis-daemon 即 Multica Client：实现注册/发现、15s 心跳、3s 轮询接单、执行、流式回传（Server↔Client 全部协议，决策二 A 撤销）；L37 离线缓冲已删除，断连一律重试→明确报错
  • App 内展示 Runtime 注册状态、心跳、当前执行的 Multica Task（L7/L8/L39）
  • 不在 JARVIS App 内实现 Multica OAuth、Issue 看板、Autopilot（H2 排除）

11.3 Q3 落地要点 — 轻量编程 UI

  • 主交互仍为 Agent 聊天；文件变更通过 Diff 面板预览和 Accept/Reject（E9）
  • 文件树用于浏览工作区结构；代码只读预览（语法高亮即可，无需完整编辑能力）
  • Agent 侧仍保留终端、Git、LSP 诊断（E3/E4/E7），LSP 服务于 Agent 自愈而非用户 IDE

11.4 Q4 落地要点 — 全自定义模型

  • Provider 配置页：选择类型（OpenAI 兼容 / Anthropic 兼容）→ 填写 Base URL、Key → 添加自定义 model id
  • 禁止在代码或配置中硬编码 gpt-4、claude-3 等预设名称
  • 连通性测试（B8）对用户填写的 model id 发真实请求验证
