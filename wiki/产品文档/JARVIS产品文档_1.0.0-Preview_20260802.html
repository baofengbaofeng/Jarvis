    §2 · product-vision

    2. 产品愿景与定位

    2.1 产品愿景

    愿景：让每位知识工作者拥有一款真正属于自己的本地 AI 工作台—— 既能像豆包一样高效处理日常办公，又能像 Cursor 一样执行编程任务， 还能通过自定义 Agent 团队实现复杂协作，且数据与密钥完全留在本机。

    2.2 产品定位

    一句话定位：JARVIS 是面向个人办公的跨平台本地 AI Agent 平台—— 豆包式交互体验 + Cursor 级编程能力 + Multica 兼容的多 Agent 协作基础设施。

    2.3 核心价值主张

    价值维度用户痛点JARVIS 解法
    统一工作台办公 AI 与编程 AI 工具割裂，切换成本高单一 App 覆盖对话、写作、编程、多 Agent 协作
    本地优先担心数据上云、API Key 泄露SQLite 本地存储、Key 加密；Provider 断连重试→明确报错（无离线本地模式）
    模型自由被绑定在单一厂商模型全自定义 Provider/模型（Q4），兼容 OpenAI / Anthropic API
    Agent 可编排单一助手无法应对复杂任务自定义 Agent + Squad 小队（Q1:A 对齐 Multica）
    生态开放工具能力受限于内置功能Skills + MCP + Plugin 扩展（G 模块）
    协议兼容无法接入现有 Agent 调度体系本机 jarvis-daemon 注册为 Multica Client，被 Multica Server 直接调度（Q2:A）

    2.4 竞品对比与差异化

    维度豆包桌面端CursorMulticaJARVIS
    办公助手★★★★★★★★★★★（D 模块全量）
    编程 Agent★★★★★★★★★★★★★（轻量形态 Q3:B）
    多 Agent 协作★★★★★★★★★★★★（Squad 对齐 Multica）
    本地/隐私★★★★★★★★★★★★★（纯本地优先）
    模型自由度★★★★★★★★★★★★★（全自定义 Q4）
    Multica 集成——★★★★★★★★★（本机 jarvis-daemon 即 Multica Client，Q2:A）
    差异化总结：JARVIS 不是任何单一竞品的替代品，而是三合一的本地 Agent 平台—— 取豆包之易用、Cursor 之编程、Multica 之协作，以本地隐私与模型自由为底座。

    5. 核心功能产品设计

    以下将需求能力 ID 转化为产品功能描述，标注交付层级与关键交互要点。

    5.1 首次引导（L1–L3）MVP

    步骤产品目标交互要点

    功能产品描述交付层级

    D5–D7 写作/PDFAI 写作助手、边写边译、PDF 伴读（中英对照、摘要）1.0.0-Preview
    D8 网页总结内置 WebView（I8）打开网页 → 一键总结1.0.0-Preview
    D9–D12 多媒体视频摘要、文生图、语音输入、文件上传分析1.0.0-Preview
    D13–D15 增强Markdown 渲染、对话导出、Prompt 模板库MVP / 1.0.0-Preview

    5.3 Agent 系统（F 模块）

    功能产品描述交付层级
    F1–F6 Agent 基础创建/编辑 Agent：名称、头像、System Prompt、绑模型/Skills/MCP、工具权限策略MVP
    F7 @唤醒对话中 @AgentName 唤醒其他 Agent 协作1.0.0-Preview
    F8/F9 Squad小队模式：Leader 接单 → @成员分派 → 遵循 Multica SOP（Q1:A）1.0.0-Preview

    5.4 编程 Agent（E 模块）— 轻量形态 Q3:B

    产品原则：主交互仍为 Agent 聊天；用户通过 Diff 面板预览和 Accept/Reject 文件变更； 不提供完整 IDE 体验（E5 Inline 补全排除）。
    功能产品描述交付层级
    E2/E3 基础执行Agent 读写工作区文件、执行 Shell 命令MVP
    E6 @引用对话中 @file/@folder/@symbol 引用上下文1.0.0-Preview
    E9 Diff 预览文件变更 Diff 面板，逐块 Accept/Reject1.0.0-Preview
    E10 Plan 模式只读分析模式，Agent 不改文件，输出计划1.0.0-Preview
    E11/K3 代码面板文件树浏览 + 只读语法高亮预览 + Diff（非 Monaco 完整 IDE）1.0.0-Preview
    E1/E4/E7–E8代码索引、Git 操作、LSP 诊断（Agent 侧）、测试修复循环1.0.0-Preview

    5.5 模型管理（B 模块）— 全自定义 Q4

    原则产品设计
    无预设模型应用内不出现 gpt-4、claude-3 等硬编码名称；用户自行注册 model id
    Provider 类型设置页选择 OpenAI 兼容 / Anthropic 兼容 → 填 Base URL + Key
    Agent 绑定创建 Agent 时从用户已注册模型列表中选择
    连通测试Provider 页「测试连接」对用户填写的 model id 发真实请求
    本机模型（移除）B11 已移除（2026-08-02 澄清：1.0.0-Preview/V2.0 均不安装本机模型）——仅云端 Provider

    6. 关键用户旅程

    6.1 MVP 核心旅程：首次使用 → 执行任务

    用户打开 JARVIS │ ▼ [L1 首次向导] ├─ 配置 Provider（OpenAI/Anthropic 兼容 + model id） ├─ 创建 Agent（名称/指令/绑模型/绑工作区） └─ 环境自检通过 │ ▼ [K1 主聊天窗口] ├─ 选择 Agent → 输入任务描述 ├─ Agent 流式回复（L5 双通道输出） └─ Agent 调用工具：读写文件（E2）/ Shell（E3） │ ▼ [Task 生命周期 L4–L6] ├─ 用户可取消 / 暂停 / 重试 ├─ 失败原因分类 + 一键重试 └─ Task 完成 → 可选系统通知（I5） │ ▼ [持久化 A6] └─ 重启 App → 会话/Agent/配置均保留（SQLite）

    6.2 1.0.0-Preview 编程旅程：@引用 → Diff Accept

    用户在主聊天选择「编程 Agent」 │ ▼ 输入：「重构 @src/utils/auth.ts，提取 validateToken 函数」 │ ▼ Agent Plan 模式（E10）可选 → 输出分析计划 │ ▼ Agent 执行：读文件 → 生成修改 → LSP 诊断（E7） │ ▼ [K3 代码面板 + E9 Diff] ├─ 文件树高亮变更文件 ├─ Diff 面板逐块展示 └─ 用户 Accept / Reject 每块变更 │ ▼ [L26 一键回滚] 可选 → Task 级撤销所有文件改动

    6.3 1.0.0-Preview Squad 旅程：Leader 分派协作

    用户创建 Squad：Leader + 成员 Agent（F8） │ ▼ 用户向 Leader 发送复杂任务：「写一份技术方案并生成示例代码」 │ ▼ Leader 分析任务 → @文档Agent 写方案 → @编程Agent 写代码 │ ▼ [L12 消息总线] Agent 间结构化通信 ├─ [L14 调用链可视化] A→B→C └─ [L15 循环检测] 防止无限委派 │ ▼ Leader 汇总 → 整体 Task 置 in_review（Multica SOP） │ ▼ 用户审批（F15 人类-in-the-loop）→ 完成

    6.4 1.0.0-Preview Multica 客户端集成旅程

    Multica Server 创建 Issue → 分配 Task │ ▼ 本机 jarvis-daemon（Multica Client）注册/发现 + 15s 心跳 + 3s 轮询接单（H1.1/H1.10） │ ▼ jarvis-daemon 领取 Task → 注入 MCP/Skills/Env（H1.6–H1.8） │ ▼ spawn jarvis-agent 执行 → 流式回传进度（H1.4） │ ▼ [L39 UI 指示] App 托盘/设置页显示注册/心跳/接单状态与当前 Task │ ▼ Task completed → Multica Server 收到结果
    §7 · ux-guidelines

    7. 交互与体验设计规范

    7.1 设计原则

    原则说明落地要求
    对话优先主交互为聊天窗口，其他面板为辅助K1 为默认视图；代码/Task 面板可切换但不抢占
    本地可信用户感知数据在本机、Key 安全设置页明确「纯本地模式」开关（J4）；Key 加密提示（J1）
    渐进披露复杂配置不阻塞首次使用L1 向导仅引导必要步骤；高级配置在设置页
    Agent 透明用户可见 Agent 正在做什么流式输出 + 工具调用可视化 + Task 日志（L5/K5）
    安全默认危险操作需确认Shell/文件删除/MCP 首次调用 → 二次确认（J2/J7）
    双语一致zh-CN / en 体验对等A11：全部 UI 文案 i18n，禁止硬编码

    7.2 关键 UI 模式

    模式参考JARVIS 实现
    主聊天豆包桌面端左侧 Agent 切换（K2）+ 中央对话区 + 底部输入框（支持 @/@file/语音）
    窗口吸附豆包侧边栏A4：贴边缩略/展开，不占满屏幕
    Diff 预览Cursor/CodexE9：逐块 Accept/Reject，非强制全量应用
    Task 看板Multica Issue 视图K4：queued → running → completed/failed 状态流
    设置页Cursor SettingsC 模块：分组 Tab（Provider/Agent/MCP/Skills/权限/高级）
    托盘菜单Multica DesktopA2/L7：Daemon 状态、快速打开、退出

    7.3 国际化要求（A11）

    项要求
    必须语言简体中文（zh-CN）、英文（en）
    覆盖范围全部 UI、系统消息、设置项、错误提示、托盘、通知
    不覆盖用户对话内容、Agent 指令、Skills 正文
    切换方式设置页语言选择；可选跟随系统

    7.4 无障碍与响应式

    • 支持键盘导航：Tab 切换焦点、Enter 发送、Esc 关闭浮层
    • 深色/浅色主题跟随 A10，与系统偏好可联动
    • 窗口最小宽度 800px；吸附模式宽度约 400px
    • 流式输出区域支持自动滚动，用户可暂停跟随

    §9 · success-metrics

    9. 成功指标与验收标准

    9.1 MVP 验收标准

    • 用户完成首次向导，配置至少 1 个 OpenAI 或 Anthropic 兼容 Provider + 1 个自定义 model id
    • 用户创建 Agent 并绑定模型，在主聊天窗口完成多轮对话（含流式输出）
    • Agent 可在绑定工作区内读写文件、执行 Shell 命令，用户可取消/重试 Task
    • UI 可在简体中文与英文间切换，无硬编码未翻译字符串
    • API Key 加密存储；危险操作有确认提示；Agent 文件访问受沙箱约束
    • 应用重启后会话与 Agent 配置持久化（SQLite）
    • 至少 1 个 SKILL.md 可绑定至 Agent 并在任务中生效；至少 1 个 MCP stdio Server 可注册并调用其工具
    • 联网搜索可返回带引用的结果；Provider 断连时重试后给出明确错误提示（无离线本地模式）
    • Agent 对工作区外的文件访问被沙箱拒绝；并发任务按配置上限排队执行

    • 编程 Agent：@引用 → Diff Accept/Reject 完整链路可用

    • 数据安全：SQLite 自动备份、配置 Schema 迁移、敏感数据擦除
    §10 · risks

    10. 产品风险与对策

    风险影响产品对策
    范围过大 1.0.0-Preview 覆盖豆包+Cursor+Multica 三产品级能力，交付延期 严格按 §8 三层模型交付；MVP 先行内测；1.0.0-Preview 增量分批
    模型配置门槛 全自定义模型（Q4）提高首次使用难度 L1 向导简化 Provider 配置；提供 Agent 模板（L30）；连通测试即时反馈
    轻量编程预期落差 用户期望完整 IDE，实际为聊天+Diff（Q3:B） 产品文案明确「Agent 驱动编程」定位；E12 外部 IDE 对接作为补充
    Multica 生态依赖 Multica 客户端模式需外部 Multica Server，用户基数有限 本地模式为默认且独立；Multica 客户端为增量能力，不阻塞 MVP
    安全信任 Agent 执行 Shell/文件操作，用户担心安全风险 沙箱默认开启（J3）；敏感操作确认（J2）；审计日志（J5）；权限分级（J6）
    i18n 质量 双语同步开发增加成本，易出现遗漏 CI 检测硬编码字符串；zh-CN/en 资源文件强制同步更新
    范围风险提示：1.0.0-Preview 功能面极大，产品团队应坚持「MVP 先发布、增量迭代」策略， 避免在 MVP 阶段引入 M4–M8 能力导致首版延期。
    §11 · confirmed-decisions

    11. 已确认产品决策

    以下决策来自需求文档 Q1–Q5，产品方案完全遵循。

    #问题决策产品影响
    Q1 多 Agent 协作是否对齐 Multica Squad？ A — 完全对齐 Squad 为 1.0.0-Preview 增量核心功能；Leader + @成员分派；遵循 Multica SOP
    Q2 Multica 服务端使用方式？ A — Multica Client（客户端协议全量） 本机 jarvis-daemon 即 Multica Client，支持 Server↔Client 全部协议并被 Server 直接调用（决策二 A 撤销）；不提供 App 内登录/Issue/Autopilot（H2 产品功能排除）
    Q3 代码编辑深度？ B — 轻量形态 产品定位为「Agent 驱动编程」；聊天 + 文件树 + Diff；无 Inline 补全
    Q4 模型接入策略？ 全自定义模式 不预设任何模型；Provider 页为核心配置入口；BYOK 为默认路径
    Q5 全局系统能力跟进时机？ B — V2.0 1.0.0-Preview 聚焦 App 内能力；全局快捷键/划词/IM 等明确不在首版
